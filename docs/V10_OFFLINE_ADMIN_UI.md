## Еталон складання

Механізм складання **Offline v9** лишається еталоном: `Excel.Application` COM → тимчасова книга → ручний режим розрахунку → відкриття вихідного XLSX → попередня перевірка VBProject → імпорт локальних модулів через `CodeModule.AddFromString` (UTF-8) → `SaveAs(...,52)` → **закрити Excel** → ZIP-перевірка `vbaProject.bin`. Без GitHub-запитів у клієнтському інсталяторі.

## Розвиток інтерфейсу

- Залишається **одна видима вкладка «Зміст»**. Решта — локальні приховані журнали та довідники. Закріплені області вимкнені.
- Кнопки **не переводять на інші аркуші**. При натисканні відкривається модальна `frmTCAdmin` із комбосписками й текстовими полями.
- VBA-модуль `TransportApp.bas` керує формою для режимів `NEW`, `START`, `FINISH`, `COST`, `CAR`, `DRIVER`, `ROUTE`, `PARKING`, `REPORT`.
- Рейси вибираються за ID зі списку з маршрутом та водієм. Статуси: **Заплановано → У рейсі → Завершено**.
- Адміністратор реєструє/редагує автомобілі, водіїв із контактами, маршрути й паркінги через вікна.
- Окремі **динамічні** журнали `TC_Рейси`, `TC_Витрати`, `TC_Події` дописують дані без створення нових аркушів на кожен рейс.
- 40 місць у наявному реєстрі водіїв (**20+ без оновлення**); 200 підготовлених маршрутів (114 імпортованих), 150 пакетів паркінгів (попередні локальні тарифи перенесені). Нові маршрути/паркінги можуть дописуватись після первинних діапазонів.
- Паливний прогноз фіксується при створенні рейсу; фактичні витрати додаються окремо.
- Резервне копіювання перед записом; відновлення лише при закритому Excel.
- Тільки **ручне** оновлення NBP. Ніяких фонових перевірок оновлень або синхронізації з GitHub.

## Важливі обмеження першого випуску

**На машині розробки немає Microsoft Excel для Windows.** Перевірені структура вихідного XLSX, його 4 діаграми, ZIP, JSON-маршрути, програмні інваріанти та наявність процедур. Саме створення `frmTCAdmin` через `VBComponents.Add(3)`, компіляція UserForm у Excel LTSC та реальні операції VBA **потребують окремого приймального тесту** і не повинні називатися повністю перевіреними до підтвердження.

Рекомендується тестування: запуск нової збірки → створити автомобіль та водія → вибрати один із 114 маршрутів → створити рейс → розпочати → витрата → завершити → перевірити фінанси та резервні копії. Реальні ПІБ/телефони/маршрути не публікувати в цьому репозиторії.

> Примітка: поточний ZIP розповсюджується як окремий файл і **не міститься** в GitHub; репозиторій зберігає еталон v9 та документацію розвитку v10.
